# AGENTS.md

## Stack
- Java 25 + Spring Boot 4.1.0 + Maven wrapper (`./mvnw`, Maven 3.9.16). `pom.xml:16` pins `java.version=25` — ensure JDK 25 is active (`java -version`).
- Spring Data JPA + MySQL 8.4 (`mysql-connector-j` runtime) in `dev`; H2 in-memory (`com.h2database:h2`, test scope) in `test`.
- **Flyway is active** (`spring-boot-starter-flyway` + `flyway-mysql`, `pom.xml:44-51`). Migrations live in `src/main/resources/db/migration/` (`V1__baseline.sql` .. `V22__rename_schema_to_english.sql`). `ddl-auto: validate` in dev — schema comes from migrations, not Hibernate. Never edit an applied migration (checksum breaks); add `V23__...`.
- MapStruct 1.6.3 + Lombok. Both must stay in `pom.xml:132-142` `maven-compiler-plugin.annotationProcessorPaths` — removing either breaks generated mappers.

## Environments / Profiles
Three Spring profiles; default is `dev` (`application.yaml:8-9`, overridable via `SPRING_PROFILES_ACTIVE`).
- **dev** (`application-dev.yaml`): MySQL `localhost:3306/sports_management`, credentials from `.env`, Flyway on, `ddl-auto: validate`, `show-sql: true` (SQL logging lives here, not in the default file).
- **test** (`application-test.yaml`): H2 in-memory `jdbc:h2:mem:sports_management_test;MODE=MySQL`, Flyway off, `ddl-auto: create-drop`, Spring Docker Compose off, `show-sql: false`. Surefire forces it — `pom.xml:151-156` sets `spring.profiles.active=test`.
- **prod** (`application-prod.yaml`): `show-sql`/`format_sql` off, Flyway on, `ddl-auto: validate`, Docker Compose off. Requires `DB_URL`, `DB_USER`, `DB_PASSWORD`, `API_CORS_ALLOWED_ORIGINS` and `API_SECURITY_TOKEN_SECRET` (boot fails without them).
- H2 is test-scoped only. Tests no longer need Docker/MySQL: service tests are pure Mockito; `AthleteRepositoryTest` uses `@DataJpaTest` and `contextLoads` boots the full context (both on H2).
- **CORS**: `api.cors.allowed-origins` (`CorsProperties`) → `CorsConfigurationSource` bean in `SecurityConfig`. Unknown origins get `403` on preflight; covered by `CorsConfigTest`.

## Database / Env
- `.env` is gitignored and **not committed**; create it from `.env.example` and fill `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_DATABASE`, `MYSQL_ROOT_PASSWORD`, `API_SECURITY_TOKEN_SECRET`. Loaded via `spring.config.import: optional:file:.env[.properties]` (`application.yaml:3`) and read at `application-dev.yaml:4-5`.
- URL dev: `jdbc:mysql://localhost:3306/sports_management?allowPublicKeyRetrieval=true&useSSL=false&serverTimezone=America/Recife` (`application-dev.yaml:3`).
- `spring-boot-docker-compose` (`pom.xml`, runtime) manages `compose.yaml` lifecycle on `spring-boot:run`; disabled under test (`application-test.yaml`).
- Migrations are the source of truth. `application.yaml` keeps `show-sql`/`format_sql` on by default; test turns SQL logging off.
- **JWT config**: `TokenProperties` (`@ConfigurationProperties(prefix = "api.security.token")`, `@Validated`) groups `secret` (`min 32`), `issuer` and `expiration` (`Duration`, e.g. `2h`). Without `API_SECURITY_TOKEN_SECRET`, boot fails. Dev uses the value from `.env`; tests use the fixed value from `application-test.yaml`.
- **`Clock` in the JWT**: `JwtService` injects the `Clock` bean (`ClockConfig`) and computes `exp` with `clock.instant().plus(properties.expiration())` — never use `LocalDateTime.now()` with a fixed offset.

## Architecture
- Entrypoint: `src/main/java/br/gov/quixada/sports/SportsManagementApiApplication.java`.
- All domains are now fully wired (entity → repository → service → controller → MapStruct mapper → DTO records): `athlete`, `category`, `club`, `competition`, `team`, `modality`, `registration` (`AthleteRegistration` + `TeamRegistration`), `match` (+ standings). Shared error handling in `common/error/` (`ApiError`, `GlobalExceptionHandler`); shared value classes in `shared/` (`Address`, `Gender`, `FullNameUtils`, `CpfUtils`); `Clock` bean (America/Fortaleza) in `config/ClockConfig.java`.
- **API versioning (native Spring 7 / Boot 4)**: `config/ApiVersioningConfig.java` implements `WebMvcConfigurer.configureApiVersioning`, resolves the version from the 1st path segment via `usePathSegment(0, ...)`, supports `1.0` and uses `1.0` as the default. Controllers use `@RequestMapping(path = "/v{version}/...", version = "1.0")`. Paths outside the `/vN/...` pattern (e.g. `/error`) are not versioned.
- REST base paths (all v1): `/v1/athletes`, `/v1/categories`, `/v1/clubs`, `/v1/competitions`, `/v1/teams`, `/v1/modalities`, `/v1/athlete-registrations`, `/v1/team-registrations`, `/v1/users`, `/v1/matches`; standings at `/v1/competitions/{id}/categories/{catId}/standings`.
- **Status filter**: all listings accept `?status=VALUE` (the resource's enum); omitted = active + inactive. `GET /{id}` still returns inactive records.
- **Competition**: `registrationStartDate`/`registrationEndDate` + `startDate`/`endDate`; status is recalculated from the dates (`CompetitionStatusScheduler`, scheduled) and `PATCH /status` only accepts `CANCELED`. Creation requires modality `ACTIVE`.
- **Registrations**: `PENDING/APPROVED/INACTIVE` occupy a slot; `CANCELED/REJECTED` free it. A team may only have one active registration per competition (checked in the service; **no DB unique**). Invalid transitions → 409. Canceling/deactivating a team cascades to athlete registrations and matches. Registration requires athlete and category `ACTIVE`; a team is only approved with ≥1 athlete `PENDING/APPROVED`; the last active athlete of an approved team cannot be removed. Reactivations revalidate the window, team, category, modality and duplication.
- **Auth (versioned)**: `POST /v1/auth/register` (`username`, `email`, `password`; role is always `USER`) and `POST /v1/auth/login` (`email`, `password`).
- **Login rate limit (A5)**: `POST /v1/auth/login` consumes two in-memory bucket4j buckets (`security/auth/LoginRateLimiter`): per IP (`max-per-ip`) and per (IP, normalized email) (`max-per-ip-email`). Limit exceeded → `429` + `Retry-After` in the `ApiError` format; success returns the attempt count. **Not a lockout**: there is no `blockedUntil` and no migration. IP = `request.getRemoteAddr()` (do not trust `X-Forwarded-For`). State lives in Caffeine, per instance.
- **`security` module**: `security/config` (`SecurityConfig`, `JwtAuthenticationFilter`, `Rest*`, `LoginRateLimitProperties`, `RateLimitConfig`, `ClockTimeMeter`), `security/jwt` (`JwtService`, `TokenProperties`), `security/auth` (`AuthController`, `AuthService`, `LoginRateLimiter`, `CustomUserDetailsService`, `UserRepository`), `security/users` (`User`, `UserRole`, `UserStatus`, `UserDetailsAdapter`, `UserController`, `UserService`, `UserMapper`, `UserSpecifications`, `UserAudit`, `UserAuditService`, `dto/*`).
- **Identity**: email is unique (`uk_db_users_email`, V13) and is the `sub` of the JWT; username is **not** unique (V14 added it, V15 removed it) and is descriptive only. The `User` entity no longer implements `UserDetails`; `UserDetailsAdapter` (a record in `security/users`) wraps the entity and returns **email** in `getUsername()`, so `Authentication.getName()` is the email.
- **Authorization** (`SecurityConfig`): `/v1/auth/**` public; `GET /v1/users/**` requires `ADMIN` or `SUPERADMIN`; writes to `/v1/users/**` and `GET /v1/users/audit` require `SUPERADMIN`; `GET /v1/**` requires `USER` or `ADMIN`; `POST`/`PATCH`/`PUT`/`DELETE /v1/**` requires `ADMIN`; other requests require `USER`. `ADMIN` carries `ROLE_ADMIN`+`ROLE_USER`; `SUPERADMIN` carries `ROLE_SUPERADMIN`+`ROLE_ADMIN`+`ROLE_USER` (`UserDetailsAdapter.getAuthorities`).
- Athlete: `GET /?name=&status=&page=&size=`, `GET /{id}`, `GET /cpf/{cpf}`, `POST /`, `PUT /{id}`, `PATCH /{id}/status`, `DELETE /{id}`. Paginated — `AthleteService.java:29` returns `Page`. Name search matches the normalized full name (`FullNameUtils.normalize`).
- **Users**: `GET /v1/users?search=&status=` and `GET /v1/users/{id}` (ADMIN/SUPERADMIN); `POST /v1/users`, `PUT /v1/users/{id}` (password optional) and `PATCH /v1/users/{id}/status` (soft delete) are SUPERADMIN-only; `GET /v1/users/audit` is SUPERADMIN-only.
- **Matches**: `GET/POST /v1/matches`, `GET/PUT /{id}`, `PATCH /{id}/status`, `PATCH /{id}/result`; they reference `TeamRegistration` (home/away). Requires registrations `APPROVED`, same competition/category, distinct teams, date within the period, and one team per round/time slot. Creating matches is allowed in a `COMPLETED` competition; in a `CANCELED` competition the match is born `CANCELED`. The `competitionId`/`categoryId`/`status` filters are combinable. Standings start with registrations `APPROVED` (0 games) and compute 3/1/0 with tiebreakers points → wins → goal difference → goals for → head-to-head → name.
- **User rules**: `ADMIN` is read-only on `/v1/users`. `SUPERADMIN` cannot create/promote `SUPERADMIN` via the API (only the `V17` seed), cannot change their own `role`/`status`, cannot edit/deactivate another `SUPERADMIN`, and may edit their own profile (keeping `role`).
- Athlete registrations have `PUT /v1/athlete-registrations/{id}` to edit only `jerseyNumber`; team registrations are immutable (cancel it and create another).
- **Physical vs logical deletion**: `DELETE /v1/athletes/{id}` is the **only** physical deletion (`AthleteService#hardDelete`): requires the athlete `INACTIVE` and with no registrations in `OCCUPY_SLOT`; it first deletes the registrations in `FREE_SLOT` (`CANCELED`/`REJECTED`) and returns `204`/`409`. All other domains use only logical discard via `status`.
- **`notes` (V21)**: free text (`varchar(500)`, optional) on `Competition`, `TeamRegistration`, `AthleteRegistration` and `Match`. **Not tied to status** and triggers nothing: accepted on `POST`, editable/clearable in any state via `PATCH .../notes` (`*NotesRequest`). It lives outside `update(...)`, which blocks inactive/canceled records — it is the path that deliberately bypasses those blocks. Absent/blank ⇒ `null`.
- **`canceledAt` (V21)**: informational, recorded only on the transition to `CANCELED` (including the bulk `MatchRepository.cancelBy*` queries, which receive the instant from the `Clock`).
- DTOs are `record`s. Mapping via MapStruct `componentModel="spring"`.

## Gotchas — Won't Find Without Reading Code
- **CPF normalization**: `shared/CpfUtils.java` strips non-digits, called in `Athlete.java` `@PrePersist/@PreUpdate` AND in `AthleteService#save` before saving (via the package-private setters `setCpfNormalizado`/`setNormalizedFullName`, which also normalize the name with `FullNameUtils`). Entity has `@Pattern("\\d{11}")` (`Athlete.java:47`) which rejects formatted CPF before normalization — fix belongs in DTOs/service, not entity.
- **MapStruct + Lombok coupling**: generated mappers go to `target/generated-sources/annotations/`. After editing `AthleteMapper.java` run `./mvnw clean compile` to regenerate.
- **`version` in `@RequestMapping` + MockMvc standalone**: without an `ApiVersionStrategy`, Spring throws `IllegalStateException: API version specified, but no ApiVersionStrategy configured` when mounting the handler. `AuthControllerTest` sets it up via `ControllerTestSupport` (`src/test/java/br/gov/quixada/sports/support/ControllerTestSupport.java` builds the MockMvc with `.setApiVersionStrategy(...)`); new tests with versioned controllers need to do the same.
- **Two security error levels**: `GlobalExceptionHandler` (`common/error/GlobalExceptionHandler.java`, `@RestControllerAdvice`) covers controller errors (validation, domain, and login `AuthenticationException` → 401). Filter errors (missing/invalid token → 401, insufficient role → 403) are written by `RestAuthenticationEntryPoint`/`RestAccessDeniedHandler` via `ApiErrorResponseWriter`. The `@RestControllerAdvice` does not reach filter exceptions.
- **Jackson 3**: `ApiErrorResponseWriter` injects `tools.jackson.databind.ObjectMapper` (the Boot 4.1 bean). The `com.fasterxml.jackson.annotation.*` annotations remain valid; what changed package is the databind.
- **MySQL error code in service**: `AthleteService.java:63` inspects `SQLIntegrityConstraintViolationException.getErrorCode() == 1062` (duplicate CPF). This branch is not exercised under H2 (unit tests mock it).
- **User registration**: `AuthService.register` pre-checks `existsByEmail` and translates a `DataIntegrityViolationException` whose `getMostSpecificCause().getMessage()` contains `uk_db_users_email` into `EmailAlreadyRegisteredException` (409). Duplicate username is allowed by design.
- **User lookup in auth**: `UserRepository.findByEmail` returns `Optional<User>`; `CustomUserDetailsService` throws `UsernameNotFoundException` when not found (the `DaoAuthenticationProvider` converts it into a `BadCredentialsException`, keeping the generic 401).
- **Invalid token in the filter**: `JwtService.extractEmail` throws `InvalidTokenException`; the `JwtAuthenticationFilter` catches it and continues the request unauthenticated (no 500/NPE). The final status is handled by `RestAuthenticationEntryPoint` (missing/invalid token → 401 JSON) and `RestAccessDeniedHandler` (insufficient role → 403 JSON).
- **Inactive user**: `UserStatus` (ACTIVE/INACTIVE, `status` column created in `V16`) is checked in `UserDetailsAdapter.isEnabled()`. The JWT filter applies `.filter(UserDetailsAdapter::isEnabled)`, so a token already issued for a deactivated user stops authenticating; login is also blocked.
- **Soft delete**: is just `status` (`ACTIVE/INACTIVE`, or `CANCELED` for competition/registration). There is no `@SQLDelete`/`@Where`: listings bring inactive records unless the client sends `?status=`; uniques (CPF, email, jersey number) remain occupied.
- **Deactivation blocks**: athlete/team/category/club/modality with active references → 409 (`ActiveReferenceException`). Competition does not block: `CANCELED` cascades to registrations and matches.
- **Category**: duplication only for an **identical age range among ACTIVE categories** of the same competition; free names and partial overlap allowed.
- **CPF**: `@CPF` active on create; `GET /v1/athletes/cpf/{cpf}` normalizes with `CpfUtils`.
- **Bootstrap SUPERADMIN**: `V17__promote_seed_superadmin.sql` promotes `admin@quixada.gov.br` (seed from `V11`) to `SUPERADMIN` and guarantees `status=ACTIVE`. The seed password is defined in `V11` and **must be rotated on first deploy** (the migration history is public); see the runbook at `docs/operacao/superadmin-recovery.md`.
- **SUPERADMIN password recovery (exactly 1, no creation/promotion via the API)**: a **server** operation, with no HTTP endpoint. `SuperadminPasswordResetRunner` (`@Profile("superadmin-reset")`) reads the email (`--reset.email`/`SUPERADMIN_EMAIL`, default `admin@quixada.gov.br`) and password (interactive console or `SUPERADMIN_NEW_PASSWORD`), re-hashes with BCrypt, reactivates and audits (`PASSWORD_RESET`). Run: `java -jar target/sports-management-api-0.0.1-SNAPSHOT.jar --spring.profiles.active=dev,superadmin-reset` (`application-superadmin-reset.yaml` uses an ephemeral port and disables Docker Compose). Full runbook: `docs/operacao/superadmin-recovery.md`.
- **User audit**: `V18__create_user_audit.sql` creates `db_user_audit`; `UserService` records `CREATE`/`UPDATE`/`STATUS_CHANGE` via `UserAuditService` (never logs the password). Read at `GET /v1/users/audit` (SUPERADMIN).
- **Password policy**: applied in `RegisterRequest` (`@Size(min = 8, max = 72)`; BCrypt ignores bytes beyond 72).
- **Per-instance rate limit**: `LoginRateLimiter` uses local Caffeine. A restart zeroes the counters and N replicas multiply the effective limit (N×); the evolution is to swap the `Cache<String,Bucket>` for a bucket4j `ProxyManager`. Cache eviction (`maximumSize`) recreates full buckets (fail-open), so monitor the size before reducing `max-keys`. Behind a proxy, `getRemoteAddr()` returns the proxy — configure `server.forward-headers-strategy=framework`.
- **`@CreationTimestamp` Hibernate-specific** (`Athlete.java`) — tied to Hibernate, not Spring Data auditing. Tests need a full context.
- **Iteration notes**: `src/main/java/br/gov/quixada/sports/iterations/pending-items.md` is the consolidated roadmap of everything not yet implemented/pending — check before large refactors. QA report: `docs/qa/relatorio-testes-unitarios.html` (tracked).
- **Git**: current work branch is `dev`; `main` receives PRs from `dev` (PR #8 already merged). No CI / lint / formatter config, no `.github/`, no `opencode.json`. `HELP.md` is Spring Initializr boilerplate.
